# 数据源评估：pvp.qq.com 与 wanplus.cn/kog

> 评估时间：2026-10-24　｜　目的：判断这两个站能否补上「真实赛事 BP 数据」这块缺口
> 原则：先读 robots，只取页面级公开 HTML，限速 2–3 秒/请求，不碰数据接口、不遍历、不绕过反爬
> 结论：**两个站都拿不到「每局 BP 明细」**。能拿到的是赛事/战队的聚合数据，价值有限。

---

## 1. robots 结论（先看规则再动手）

| 站点 | robots 原文 | 判定 |
|---|---|---|
| `pvp.qq.com` | `/robots.txt` → **404**（无此文件）；父域 `www.qq.com/robots.txt` 为 `User-agent: *` / `Disallow:`（空） | 无禁止项，页面级抓取允许 |
| `www.wanplus.cn` | `User-agent: *`；`Disallow: /*?*`、`/data/`、`/js/`、`/images/`、`/assets/`、`/static/`、`/ajax/` | **带查询参数的 URL 与 `/data/`、`/ajax/` 目录明确禁止 → 其数据接口不能碰** |

⚠️ wanplus 的赛事 BP、英雄榜数据全部走 `/data/` 或带 `?` 的接口，因此**按规矩这一整块必须放弃**。

---

## 2. 实际渲染测试（各站只取了 2–3 个页面）

### 2.1 pvp.qq.com —— 全是 JS 壳

| 页面 | 结果 |
|---|---|
| `web201605/herolist.shtml`（英雄列表） | 200，42.6 KB，GBK；可解析出 92 个 `herodetail/<id>.shtml` 链接 —— **唯一有价值的静态结构**（英雄 id 映射） |
| `matchdata/schedule.html?league_id=20260004`（赛事数据中心·赛程） | 200，19.6 KB；可见文本 1,181 字，全是 `A队伍名称`、`02.22` 这类**占位符**，数据由 JS 拉接口 |
| `web201706/newsdetail.shtml?tid=799289`（KPL 战报） | 200，18.3 KB；**可见文本仅 123 字**，正文同样由接口加载 |

**判定**：pvp 的赛事中心、战报正文都无法从 HTML 取到。唯一能稳定拿的是英雄列表结构与 id。

### 2.2 wanplus.cn/kog —— 部分 SSR，核心数据仍走接口

| 页面 | 结果 |
|---|---|
| `/kog`（首页） | **SSR 可用**：真实赛程与比分，如「北京JDG vs 广州TTG 10-27 18:00」「杭州LGD.NBW 4:0 南通Hero久竞」 |
| `/kog/event`（赛事库） | **SSR 可用**：2026 KPL 年度总决赛（2026/10/02–11/14，进行中）、2026 KPL 夏季赛、挑战者杯等，带起止时间 |
| `/kog/teamstats`（战队数据） | **SSR 可用**：真实战队表——武汉eStarPro KDA 9.3、场均击杀 13.4、一血率 75.0%；北京WB 4.4 / 33.1 助攻 / 一血率 50.0% 等 |
| `/kog/skill/hero`（英雄榜） | **空壳**：只有表头「英雄 / 出场率 / 被禁率 / 胜率 / KDA」和「选择一个英雄可查看它的深度数据」，行数据由接口填充 |
| `/kog/event` 里的赛事详情链接 | **0 个静态 `<a>`**（动态绑定）→ 每局 BP 无法通过页面路径进入 |

**判定**：wanplus 能拿到的是「赛事日程 + 战队聚合数据」，拿不到「单局 pick/ban」。

## 3. 这两个站能给我们什么（合规可用部分）

| 可得数据 | 来源 | 对 BP 平台的价值 | 建议 |
|---|---|---|---|
| 赛事日程与比分 | wanplus `/kog`、`/kog/event` | 低（只说明谁在打） | 可做「赛事日历」展示，价值有限 |
| 战队聚合数据（KDA/经济/一血率/场均时长/控龙） | wanplus `/kog/teamstats` | **中**：可做「对手/战队风格画像」——一血率高的队偏前期，场均时长长的队偏运营 | 低频人工查阅，不建议自动化 |
| 英雄 id ↔ 名称映射 | pvp `herolist.shtml` | 低（本地已有 133 英雄主表） | 不需要 |
| 单局 BP（pick/ban 顺序） | **两站均不可得** | 高（正是我们缺的） | 见下方替代方案 |

## 4. 缺口：真实 BP 数据的合规替代路径

按优先级：

1. **人工记录（推荐，最快）**：KPL 每局 BP 有官方直播与赛后图文，人眼记录 10–20 场关键对局即可校准「体系 vs 体系」的胜负关系。
   模板已备好：`data/tournament-bp-template.csv`（赛事/日期/队伍/蓝红方/ban×5/pick×5/胜负/备注）。
   10 场约 30–40 分钟，比任何爬虫都划算，且完全合规。
2. **赛事复盘图文（合法抓取）**：虎扑、9game、搜狐的 KPL 赛后分析是 SSR，本次调研已用过（如「狼队带火小乔钟馗体系」就是这类来源）。适合拿「某队用了什么体系」的叙述，不适合拿完整 BP 表。
3. **不接营地/不逆向接口**：王者营地需登录态，v2 已明确不接；wanplus 与 pvp 的接口在 robots 与「不爬」原则下都不碰。
4. **若未来要规模化**：找有公开 API 或授权数据的第三方（需商务/授权），或自建人工标注流程（每场 5 分钟，可持续）。
