# v2.5 算法调整：pick 不能只看梯度（ban 仍然可以）

> 状态：**已落地**（2026-10-24）
> 用户口径：低梯度英雄可能有奇招，高梯度英雄也不能无脑 pick；**ban 倒是可以按梯度**。
> 数据依据：2026 KPL 春季赛 + 挑战者杯 + 夏季赛 **1323 局**（`data/kpl-bp-2026-all.json`，零失败采集）

---

## 1. 数据证据（这是调整的全部理由）

### 1.1 梯度与胜率几乎无关

| 梯度 | pick 次数 | 出场占比 | 胜率 |
|---|---|---|---|
| T0 | 2,504 | 94.6% | **50.8%** |
| T0.5 | 1,392 | 52.6% | **51.6%** |
| T1 | 6,531 | 246.8% | 49.8% |
| T2 | 2,146 | 81.1% | 48.7% |
| T3 | 496 | 18.7% | 49.0% |
| T4 | 124 | 4.7% | 50.0% |

**T0 只比 T2 高 2.1 个百分点**，T0.5 甚至最高。梯度能表达「BP 优先级」（该 ban 谁、该先抢谁），但**几乎不能预测胜负**——这正是「高梯度不能无脑 pick」的证据。

> 注意：KPL 有选择效应（强队拿弱英雄也能赢），所以差距被压缩；但方向明确——梯度不是胜负的主要解释变量。

### 1.2 被克制强度与胜率单调相关

| 被克程度 | 对局侧数 | 胜率 | 其中含 T0 的胜率 |
|---|---|---|---|
| 几乎不被克 | 138 | **55.1%** | 51.8% |
| 中度被克 | 288 | 52.1% | 52.4% |
| 重度被克 | 2,220 | **49.4%** | 50.2% |

被克从「几乎不被克」到「重度被克」，胜率掉 **5.7 个百分点**——比梯度差（2.1 点）更显著。**「被针对」比「梯度低」更能决定成败。**

### 1.3 大样本修正了一个短期偏差

钟馗的 KPL ban 率：年总 159 局里是 **34.6%**（小乔钟馗短期火热），全年 1323 局里只有 **11.9%**。单赛事样本的短期波动，在全年样本下被抹平。

## 2. 已改的三处

### 2.1 `PICK_PHASES`：先抢阶段不再「只看强度」

| 手位 | tier | counter | countered | synergy | compNeed | combo |
|---|---|---|---|---|---|---|
| 1-2 先抢 | 3.0 → **2.4** | 0.25 → **0.4** | 0.5 → **0.7** | 0.7 → 0.8 | 0.4 → 0.5 | 1.0 |
| 3 补强 | 2.0 → **1.8** | 1.1 | 1.0 | 1.1 | 1.0 | 1.0 |
| 4-5 克制 | 0.5（不变） | 3.0（不变） | 1.0 | 0.9 | 0.9 | 0.8 |

- 强度系数降 20%，省下的空间给「被克制（0.7）」「组合（1.0）」「熟练度」。
- 后两手克制阶段**完全不动**（原本就是给低梯度英雄留的路）。
- `hint` 文案同步改为「优先强势，但被针对/不会玩就要让位」。

### 2.2 `MASTERY.flat`：绝活/仅会玩的分差翻倍

| 档位 | 旧 flat | 新 flat |
|---|---|---|
| 绝活 best | +1.5 | **+3.0** |
| 正常 normal | 0 | 0 |
| 仅会玩 basic | −1.5 | **−3.0** |

含义：「T0 但我不会玩」要真的吃亏，「T2 但是我绝活」要能顶上来。basic 的 `risk`/`counterGain` 不变（仍只在净对位 ≤0 时扣 flat）。

### 2.3 新增「通用组合加成」（`comboBoostOf`）——**不需要预选**

这是本轮最关键的新能力：以前只有「预选某套阵容」才有组合加成，现在**任何情况下**只要我方已选与候选能凑成一套组合，就给分。

```js
// web/engine.js
function comboBoostOf(ctx, hero, ally, activePresetId) {
  // hero 属于某 combo.core，且我方已有 ≥1 件核心件
  // 命中 2 件 → 潜力小分 3 × 档位权重
  // 凑满 core → 成型大分 15 × 档位权重（S=1.0 / A=0.7 / B=0.4）
  // 若该组合正是当前预选，则跳过（presetFitOf 已计分，避免双计）
}
```

接入点：`breakdown.combo`，并随阶段衰减（先抢/补强 1.0、克制 0.8）。
UI：候选卡评分明细新增「组合 +15」一项，理由里显示「凑成「小乔钟馗」」。

**实测效果**（我方已选 钟馗 + 公孙离，第 3 手）：

```
小乔   T1  score 30.18  combo 15 | 凑成「小乔钟馗」          ← T1 压过 T0
镜     T0  score 23.48  combo 1.2| 组合进度「KPL经典均衡」2/5
沈梦溪 T0.5 score 18.44 combo 0
墨子   T2  score 10.98  combo 0
```

这正是「低梯度奇招」：**小乔单卡 T1，但因为能凑成 S 档组合，排到了所有 T0 前面。**

## 3. 没有改的（有意保留）

| 项 | 为什么不动 |
|---|---|
| **Ban 打分**（`banScoreOf`） | 用户明确「ban 倒是可以按梯度」。仍是 tier 权重 10× 主导、T0 必排 T1 前，两套 ban 率（`integration.score.ban`）怎么接见 [feature-ban-kpl-integration.md](feature-ban-kpl-integration.md)（方案待批） |
| 克制/被克的**数据** | 只调权重（countered 0.7），不改 `relations.json`——数据是天元口径 |
| 分路硬约束（v2.2） | 「选了射手不再推射手」仍然生效，不因组合加成突破 |
| 预选路径（v2.4） | `presetFitOf` 完全不动；通用组合加成会跳过当前预选组合，避免双计 |

## 5. 还可以往哪调（留给下一轮）

1. **tier 系数再降**：数据看 T0 只比 T2 高 2.1 点，`2.4` 仍可能偏高；可试 `2.0`（改动只在一个数组里）。
2. **组合成型分再抬高**：当前 S 档成型 +15（约半个 T0 档）。若希望「凑齐就压过一切」，可提到 +20~25。
3. **countered 权重**：数据显示被克影响 5.7 点，当前 0.7；可试 `0.9`。
4. **按位置差异化**：先抢（1-2 手）本就该更看强度，后手更看克制——现有三阶段已体现，可再细化到「对手已选 N 人」的情况。

> 所有参数集中在 `web/engine.js` 的 `PICK_PHASES` / `MASTERY` 与 `comboBoostOf` 的两个常量里，改一个数即可，改完跑 `test-engine` 就能看到排序变化。
