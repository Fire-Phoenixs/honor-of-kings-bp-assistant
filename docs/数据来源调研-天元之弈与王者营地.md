## 1. 天元之弈：实测可用接口清单

站点是 Next.js + Prisma，前端直连 `/api/*`，**全部匿名可访问**（无需 cookie/token）。
robots.txt：`User-Agent: * / Allow: / / Disallow: /stats/` —— `/api/` 不在禁止列表。
站点返回里带 `serverCached:"引用麻烦注明出处233"`，即**要求注明出处**（我们会在页脚/README 标注）。

| 端点 | 参数 | 返回（关键字段） | 我们用它做什么 |
|---|---|---|---|
| `/api/allheroes` | — | `id, name, avatarUrl, roles(中文分路)` 133 条 | 英雄主表 + 分路，与本项目 `heroes.js` **133↔133 完全对齐** |
| `/api/global/tier` | `date=YYYY-MM-DD` | `tierInRole, rankInRole, finalNormalizedTierScore, trueHeroPowerInRole, role, lowPick, highBan` 133 条 | **梯度表**：T0/T0.5/T1/T2/T3/T4（实测分布 11/7/44/46/18/7），替代「我编一份 T 度」 |
| `/api/herostats` | `date`, `gameMode` | `winRate, pickRate, banRate, winRateDelta, qAreaTop10Power...`（135 条 = 133 + 李信光/暗） | 强度权重、ban 率参考 |
| `/api/hero/analysis` | `heroId` | `counters[], counteredBy[], goodSynergies[], badSynergies[]`，每条含 `heroName, totalMatches, advantageIndex / synergyIndex` | **克制表 + 配合表**，统计得出，带样本量（张良 counters 44 条 / 瑶 counteredBy 54 条） |
| `/api/hero/bp` | `heroId`, `date` | `overallStats{蓝/红胜率、早选/晚选胜率}`, `pickOrderStats[7]{slotLabel, winRate, pickRate}` | **顺位权重（§6.4）用真实数据校准**：实测槽位 = 蓝1楼 / 蓝2,3楼 / 蓝4,5楼 / 红1,2楼 / 红3楼 / 红4楼 / 红5楼 |
| `/api/detail/specifyherostats` | `date, position, heroId` | 单英雄单分路的 `winRate, pickRate, goldMedalRate...` | 需要「某英雄在某路的真实强度」时用 |
| `/api/herostats/combined` | `date, heroId` | 分路 pick/win、召唤师技能胜率 | 二期（出装/技能不在 BP 范围） |

### 1.1 关键映射（已从 JS 源码确认）

- `gameMode`：**1=全分段，3=1350+，4=顶端排位，5=巅峰千强**（0/2 无效返回空数组）。
- `position`（specifyherostats / 分路）：**0=对抗路，1=中路，2=发育路，3=打野，4=游走**。
- `date`：只接受 `YYYY-MM-DD`；传别的格式报 400「日期格式无效」。
- 变体英雄：`李信(光)/李信(暗)` 的 `heroId` 为 50701/50702，`baseHeroId=507`，聚合到「李信」。

### 1.2 数据新鲜度

| 日期 | 结果 |
|---|---|
| 2026-10-24（今天） | 400 `您当前时段只能访问 2026-10-23 及之前的数据` |
| 2026-10-23 | ✅ 135 条 |
| 2026-10-22 | ✅ 135 条 |

即：**T-1 数据，日更**。做 BP 平台完全够（版本内梯度不会一天一变）。

### 1.3 实测样例（供验收对照）

- 梯度：`2026-10-23` → 马超 `打野/对抗路` **T0**，分数 78.74；大乔 T0 / 75.05；阿古朵 T1 / 59.22。
- 禁率（全分段 gm=1）：墨子 67.13% → 庄周 52.63% → 盾山 42.96% → 瑶 40.31% → 金蝉 38.48%。
- 禁率（1350+ gm=3）：海月 75.18% → 盾山 69.81% → 少司缘 57.77% → 敖隐 44.74%。
- 张良 BP 顺位（红方末选 = counter 位）：红5楼胜率 **52.68%**，蓝1楼 47.75%，蓝4,5楼 51.23% —— 直接量化了「末选 counter 位」的价值。
- 克制：廉颇 `counters` 含 妲己 +7.4 / 吕布 +5.64；`counteredBy` 含 云中君 -7.78 / 东皇太一 -6.97（负号=被克）。

### 1.4 采集成本估算（v1 全量一次）

| 数据 | 调用数 | 频率建议 | 耗时 |
|---|---|---|---|
| 英雄表 + 梯度 | 2 | 1 次/天 | 瞬时 |
| 胜率/禁用（1 个分段） | 1 | 1 次/天 | 瞬时 |
| 克制/配合分析 | 133（每英雄 1 次） | 串行 2 req/s + 失败重试 | ≈ 70 秒 |
| BP 顺位 | 133 | 同上 | ≈ 70 秒 |
| 按路强度（按需，只对入池英雄） | ≤ 池内英雄数 × 分路 | 懒加载 | 按需 |

实现约束：**串行 + 500ms 间隔 + 指数退避重试**，不做并发轰炸；每天最多一轮（数据 T-1 日更，无需高频）。

## 2. 王者营地：实测被拒，按你的要求停手

```
POST https://kohcamp.qq.com/hero/getmaintranklist
body: {"recommendPrivacy":0,"segment":4,"position":0}
→ HTTP 200 {"returnCode":"-30314","returnMsg":"登录态参数不全"}
```

同样头部的第二个请求（segment=1）同样被拒，**没有重试、没有尝试拼 token**。

### 营地能补什么（如果要）

| 能力 | 接口 | 需要登录 | 对 BP 平台价值 |
|---|---|---|---|
| 官方策展 T0~T4 梯度（按分路） | `/hero/getmaintranklist`（segment 1/3/4/5，position 0~5） | 是 | 中：可与天元的数据推算梯度交叉校验 |
| 英雄资料/技能/定位 | 营地英雄维基类接口 | 是 | 低：分路信息天元已有 |
| 战力榜/皮肤/个人战绩 | `kohsocialapp` 系列 | 是（CK） | 无：BP 决策不需要局内/个人数据 |

### 登录后的取法（等你决定要不要）

- 需要你提供**营地登录后的 CK**（cookie 里的 `userId` + `token`），或由你在本机浏览器登录后我读取登录态；
- 社区项目 `WzryUID` 明确警告：**CK 有账号风控风险，建议用小号 CK**；且营地数据仅供个人研究，不得分发。
- 我不会做任何绕过鉴权的尝试（模拟登录、破解签名、爆破 token 一律不做）。

**建议**：v1 不接营地。等 v1 跑起来（天元数据 + 人工标签），若发现梯度与实际体感偏差大，再决定要不要你用营地做一次官方榜交叉校验。

## 3. 对原计划的影响（重要）

原计划 §6.3 倾向「B：LLM 生成骨架 + 你纠错」。现在有真实数据源，**数据来源策略改为**：

| 数据 | 新来源 | 人工介入 |
|---|---|---|
| 梯度 T0~T4 | 天元 `/api/global/tier`（133 条，带分数） | 0（可在页面覆盖个别英雄） |
| 克制表 | 天元 `/api/hero/analysis` → `counters` 正负号拆分（`advantageIndex > 阈值` 才收） | 0，但需设阈值和样本量下限（建议 totalMatches ≥ 150） |
| 配合表 | 同上 → `goodSynergies`（`synergyIndex > 阈值`） | 0，同样设阈值 |
| 顺位权重 | 天元 `/api/hero/bp` 的 7 个槽位胜率 | 0，直接从数据拟合 |
| 池存活率/阵容体检 | 引擎计算 | 0 |
| **标签（前排/开团/保护/控制/爆发…）** | **天元没有，营地也没有** | **仍需人工/LLM 打标（133 英雄 × 2-4 标签）** |

也就是说：**唯一还需要主观知识的是标签体系**，而它正好是最容易人工审的（我可以在页面上做成「点选标签」的形式让你校正，或者在生成初稿后你只在错的上面点一下）。

数据质量风险从「克制表全是主观」降到「克制表是统计值，只需要选阈值」——这是质的改善。
