# 王者荣耀五排 BP：强势组合与克制关系调研

> 调研时间：2026-10-24　｜　用途：给本平台（五排 BP）补「组合」这一维的数据与规则
> 原始素材：`data/research/combos-raw.md`（31 条组合）、`data/research/counters-raw.md`（35 位英雄克制明细）
> 结构化数据：`data/combos.json`（引擎可消费）
> 版本口径：当前 S45 前后。资料里 2022–2023 年的条目已标注，机制可参考、强度不可直接套。

## 0. 结论先行

**1）「一个强势组合大于一切」这个判断，在数据和实战里都站得住。**
最硬的例子是养猪流：核心输出后羿是 **T2**，明世隐 **T4**、庄周 **T4**，单看梯度这套阵容根本不该被选；但五人成型后是公认最难反制的上分体系（虎扑原话「流水的英雄强度铁打的养猪」，230 亮）。小乔+钟馗同理——钟馗 T2、小乔 T1，却在 2026 KPL 巅峰对决里被双方镜像锁死，把鲁班大师、盾山、沈梦溪这些 T0 中辅全挤出了场。
**组合的价值来自「机制互补」，不来自单卡强度相加，所以它不能靠梯度分体现。**

**2）BP 上的正确顺序是「先定体系，再谈克制」。**
先确定我方要打哪个体系（看池子里谁有体系核心），再在这个体系内挑人；克制是用来「补最后两手」和「拆对面组合」的，不是用来拆自己体系的。

**3）拆组合比克制单个英雄更有效。**
组合都是「核心件 + 配件」结构：养猪流的庄周（群体解控）、乔离的大乔、小乔钟馗的钟馗、刀枪炮的墨子。**打掉核心件，整套体系立刻降级**，这比去 counter 一个 T0 单卡收益高得多。

**4）本地统计只能覆盖双人、且只保留强信号，体系层必须人工补。**
`data/relations.json` 的 1201 条 synergies 里，本次调研的 28 组知名组合只有 **7 组**有统计记录（覆盖率 25%），但这 7 组**全部为正相关、没有一条反向**——统计可信，只是覆盖不足。更关键的是统计结构上只能表达「两人」，表达不了「五人体系」。

**5）数据整合口径（重要）：三方并列；单卡与组合分离，组合只在成型时结算。**

- **天元**（tiers / counters / synergies）与 **KPL**（159 局 ban/pick/胜率）**都值得参考**，不是主从关系；
- **单卡价值只由单卡信号决定**（天元强度分），**不掺组合**——钟馗单拿就是 T2，不会因为「能凑小乔钟馗」被抬高；
- **组合知识是重要补充，但它的价值只在「拿齐那一刻」结算**（≈两个 T0 的强度增量），由引擎在拿到核心件时给分，而不是摊到单个英雄头上；
- 整合结果：`data/integration-v1.json`（v2.0，脚本 `tools/integrate-data.mjs`，参数在文件顶部 CONFIG）：
  - `score.solo` = 天元强度分（0–1，**不含组合**）
  - `score.ban` = 天元 ban 率 55% + KPL ban 率 45% + 单卡强度 20%
  - `comboPotential` = 组合归属，**仅作提示，不参与任何排序**
- 两套 ban 率揭示的是**不同东西，所以互补而不冲突**：
  - **天元 ban 率 = 路人局对手会 ban 谁**（墨子 66.5%、庄周 52.3%、金蝉 38.8%、瑶 38.3%）；
  - **KPL ban 率 = 职业体系件价值**（鲁班大师 87.4%、关羽 54.7%、赵云 43.4%、哪吒 32.7%）；
  - **两边都高 = 机制性威胁**（盾山 42.0% / 69.8%、钟馗 36.9% / 34.6%）。

## 1. 证据：为什么组合能压过梯度

### 1.1 单卡梯度 vs 组合强度（本地 `data/meta.json` 实测）

| 组合 | 核心英雄当前梯度 | 组合地位 |
|---|---|---|
| 养猪流（四保一） | 后羿 **T2**、明世隐 **T4**、庄周 **T4**、太乙真人 T1 | 公认最强上分体系之一，BP 里要专门 ban 庄周、宫本、沈梦溪 |
| 小乔 + 钟馗 | 钟馗 **T2**、小乔 **T1** | 2026 KPL 巅峰对决固定中辅，双方镜像 |
| 刀枪炮 | 沈梦溪 T0.5、百里守约 T1、墨子 **T2** | 2→3→5 人可裁剪，前期到中期无明显弱势期 |
| 僵王博士（鲁班七号 + 盾山） | 鲁班七号 **T2**、盾山 T0 | 发育路 T0 组合，对线强度「自带顺风」 |
| 元狄（狄仁杰 + 元辅） | 狄仁杰 T1、元辅 T0 | 被认为是僵王博士的「下位替代」，被其血脉压制 |

**可提炼的规则**：只要一个组合的「机制闭环」成立（控制→输出、解控→站桩、复活→容错、刷大→爆发），它对局强度就不受成员单独梯度约束。上手 BP 时应该先看**我方池子能不能凑出闭环**，再看梯度。

### 1.2 一个反直觉的数据信号：协同质量靠「控制」，不靠「保人」

把 `relations.json` 里每个辅助英雄作为协同方出现的组合汇总（平均 `idx` = 协同强度指数）：

| 协同锚点 | 组合对数 | 平均 idx | 总样本 | 解读 |
|---|---|---|---|---|
| 东皇太一 | 6 | **4.90** | 2,681 | 压制型硬控，配合质量最高 |
| 庄周 | 9 | **4.28** | 4,180 | 群体解控是「体系级」能力 |
| 鬼谷子 | 30 | 4.22 | 19,025 | 强开团，拉到就赢 |
| 张良 | 32 | 3.91 | 21,256 | 点控压制 |
| 桑启 | 13 | 3.31 | 9,644 | 续航 + 转线 |
| 盾山 | 60 | 3.28 | **120,646** | 保人/挡弹道，覆盖最广 |
| 大乔 | 64 | 3.15 | **169,932** | 体系型（电梯流），场次最多 |
| 太乙真人 | 50 | 3.08 | 99,261 | 经济 + 复活 |
| 苏烈 | 30 | 2.73 | 120,339 | 强开 + 溅射 |
| 鲁班大师 | 28 | 2.58 | 65,051 | 保护/位移 |

**结论**：配对数量多的是「保人型」（盾山、大乔、太乙真人），但**平均协同质量最高的是「控制型」**（东皇、庄周、鬼谷子、张良）。含义是——
- 想稳定上分：拿控制型组合（先手能开、反手能保）；
- 保人型组合（盾山/大乔）吃操作与默契，配合不好只是「多一个盾」。

## 2. 体系级强势组合（5 人）

> 评价列：**优先级 S/A/B**（本平台建议的组合权重档）、**证据**（来源条数/年份）

### 2.1 刀枪炮（消耗 + 视野 + 边路牵制）——优先级 S

| 位 | 英雄 | 说明 |
|---|---|---|
| 发育路 | 百里守约 | 二技能伤害高，前期两枪打崩对线 |
| 游走 | 墨子 | 二技能定身，「对面不动就能狙中」；出肉为主 |
| 中路 | 沈梦溪 | 大招 + 梦魇之牙挂重伤，专治奶妈 |
| 对抗路 | 暗信（李信） | 兵线压力，逼对面分人 |
| 打野 | 自由位 | 选强势灵活打野即可，体系配角 |

- **强势期**：前期到中期，来源称「没有明显弱势期」
- **机制**：定身 → 狙击必中；重伤 → 奶不回来；双视野 → 难被偷；边线压力 → 对面凑不齐五人冲三人组
- **反制**：后羿这类超远程强开；贴身猛冲（三人组都脆）；先清视野点再绕后
- **可裁剪**：双人=墨守成规（见 3.1），三人=+沈梦溪
- **证据**：虎扑 2026-07-20（medium，但守约+墨子另有 2 源互证）
- **本地统计**：三对组合均无记录（阈值裁掉/样本不足）

### 2.2 养猪流（四保一）——优先级 S

| 位 | 英雄 | 说明 |
|---|---|---|
| 核心输出 | 后羿（可换鲁班七号、伽罗等呆射） | 吃全队资源，经济碾压 |
| 游走/保人 | **庄周（不可替代）** | 群体解控，防强开 |
| 辅助 | 明世隐 | 前期增伤，加速发育 |
| 保护位 | 太乙真人 / 张良 / 盾山（三选一） | 经济+复活 / 先手控 / 挡伤害 |
| 对抗路 | 刘邦 | 带最远线 + 大招护盾免伤保 C |

- **强势期**：中期经济差成型后
- **机制**：庄周群体解控是全峡谷唯一，没有它神装后羿也会被控死；明世隐放大前期；太乙真人给经济与第二条命
- **反制**：**优先 ban 庄周**（虎扑共识「庄周一 ban，养猪队就老实」）；ban 宫本、沈梦溪、吕布（9game 的三种 ban 思路）；强带线偷家（怕大乔/刘邦式运营）
- **证据**：搜狐 2025-07-28 + 9game 2025-12-05 + 虎扑 2024-08-27 讨论（medium-high，跨源一致）
- **本地统计**：庄周+明世隐、后羿+庄周、后羿+明世隐 **全部无记录**；明世隐作为协同锚点出现 **0 次**
- ⚠️ **这条必须人工补**：它是全网公认最强体系，而我们的数据层完全看不到它

### 2.3 小乔 + 钟馗（中辅秒杀）——优先级 S

| 位 | 英雄 | 说明 |
|---|---|---|
| 中路 | 小乔（可用妲己/安琪拉/王昭君替代，强度递减） | 二技能前摇短，接钩即控 |
| 游走 | 钟馗 | 钩子 CD 短、空钩成本低，勾中关键几次即崩盘 |
| 发育路 | 抗压射手：敖隐 / 虞姬 | 中辅绑定，射手必须能单人抗压 |

- **强势期**：中期
- **机制**：钟馗钩中瞬间小乔二技能补控 → 钟馗大招续控；小乔伤害足，控住期间能秒坦克。钟馗单独出钩必须秒接大（空钩=大招进 CD），有小乔就不必
- **反制**：庄周（解控，钩过来也能散）；分散站位；针对射手单人抗压的发育路
- **证据**：搜狐 2026-09-04（KPL 巅峰对决固定中辅，双方镜像）+ 9game 双排组合条（medium）
- **本地统计**：小乔+钟馗无记录

### 2.4 僵王博士（鲁班七号 + 盾山，发育路体系）——优先级 A

- **机制**：盾山一技能带鲁班穿墙且可边移动边扫射，解决鲁班「扫射罚站」的死穴；盾山长按普攻附带减速，1 级消耗离谱
- **反制**：绕后/位移切鲁班本体；盾山 ban 率高，拿不到即失效
- **证据**：网易 2026-07-31（发育路 T0 组合）+ 17173 盾山机制文（high）
- **本地统计**：鲁班七号+盾山 idx 3.88 / 样本 6,765（**正相关，大样本**）

### 2.5 乔离（公孙离 + 大乔）——优先级 A

- **机制**：大乔二技能送回家，公孙离位移/传送立刻回线；越塔击杀后马上补状态再上线，容错极高
- **反制**：先掐大乔（二技能一断，越塔与续航全失效）；抓二技能落点
- **证据**：ZOL 2025-11-24 + 小米 2022（high）
- **本地统计**：公孙离+大乔 idx 3.40 / 样本 4,908（正相关）

### 2.6 朵莉亚刷大·双边体系（无限大）——优先级 A

| 位 | 英雄 | 替补 |
|---|---|---|
| 发育路 | 蚩奼 | 狄仁杰 / 艾琳 |
| 对抗路 | 曹操 | 哪吒 / 狂铁 |
| 中路 | 武则天 | 女娲 / 甄姬 |
| 打野 | 铠 | 宫本武藏 / 杨戬 |
| 游走 | 朵莉亚 | 盾山 / 少司缘 |

- **机制**：朵莉亚大招给队友刷新大招——前期给铠/曹操/蚩奼刷大，后期给武则天刷双大；曹操、蚩奼双形态兼半肉，无传统大肉也够坦
- **坑点**：**前期不要给武则天刷大**，会把她大招封印约 100 秒
- **反制**：抢前期（这套前期弱）；ban 朵莉亚即拆
- **证据**：OPPO 论坛 2025-12（medium，单源转载）
- **本地统计**：朵莉亚+莱西奥无记录（朵莉亚类组合整体数据稀薄）

### 2.7 双坦不死流（双前排 + 控制链）——优先级 B

夏侯惇（对抗）+ 白起（打野）+ 海月（中）+ 莱西奥（发育）+ 孙膑（游走）
- **机制**：双前排互相拆火，一个被集火另一个接管；白起嘲讽开团，孙膑加速让双坦能威胁后排；10–18 分钟最无解
- **反制**：**必 ban 吕布（真伤）+ 庄周（解控）**；拖到 20 分钟后靠带线牵制
- **证据**：小米 2023-01（S30 版，medium，强度需复核）

### 2.8 带线团战结合（边路牵制流）——优先级 B

梦奇（对抗）+ 亚连（打野）+ 暃（中，⚠️来源如此标注、与常规分路不符）+ 敖隐（发育）+ 桑启（游走）
- **机制**：五个位置都能带线也能参团，靠转线拉扯，无极端偏科
- **反制**：抓带线点、逼正面 5v4；对线期压梦奇/敖隐
- **证据**：搜狐 2026-06（medium）；「暃走中路」存疑

### 2.9 快攻拉扯流 —— 优先级 B

廉颇（对抗）+ 空空儿（打野）+ 元流之子·刺客（中）+ 敖隐（发育）+ 瑶（游走）
- **机制**：空空儿偷对面装备分给队友（核心大件被偷=输出砍半）；元流之子刺客大招减半 CD 连续进场；廉颇霸体+20% 减伤三连锤
- **反制**：拖后期（越拖越弱）；打断廉颇开团；抓空空儿进场空窗
- **证据**：搜狐 2026-06（medium）

### 2.10 其余两个当前版本候选（证据弱，仅记录）

- **大禹手长消耗队**：王维（中）+ 海诺（对抗）+ 阿古朵（打野）+ 守约（发育）+ 大禹（游走）——S45 微博单源（low），缺硬开团。
- **安琪拉推进队**：杨戬（对抗）+ 刘备（打野）+ 安琪拉（中）+ 海诺（发育）+ 刘禅（游走）——S45 微博单源（low）；「雾行千山」说法未验证。
- **KPL 经典均衡**：廉颇 + 镜 + 不知火舞 + 公孙离 + 大乔——2019/2020 巅峰之夜经典（medium，非当前强度榜），但「开团+保护闭环 + 乔离下路」的结构至今可复用。

## 5.2 真实 KPL 校验（159 局，2026 KPL 年度总决赛）

> ⚠️ **口径（2026-10-24 二次修正）**：本节 KPL 数据**与天元并列参与整合**，不再是「仅参考」。
> 融合权重见 §0 第 5 条与 `data/integration-v1.json` 的 `config`；组合知识权重最高（pick 分里占 55%）。
> KPL 与排位环境确有差异（教练 BP、针对性 ban、执行度），所以两套 ban 率**按用途分工**而不是互相覆盖。
>
> 数据来源：pvp.qq.com 赛事数据中心页面自身调用的官方赛事接口（`prod.comp.smoba.qq.com/leaguesite/*`，robots 404）。
> 采集口径：只取该赛事 **40 场已结束比赛 / 159 局**，串行、间隔 0.8s、零失败（见 `tools/collect-kpl-bp.mjs`）。

**三个直接结论**：

1. **钟馗（T2）被 ban 34.6%，比一半的 T0 还高** —— 职业队不是怕钟馗这个英雄，是怕「钟馗 + 小乔」这套组合。这是「组合价值无法被单卡梯度表达」的一条很直观的旁证（职业环境，仅参考）。
2. **盾山被 ban 69.8%** —— 意味着僵王博士体系在 KPL 基本拿不到（本样本里只出现 1 局，且赢了）。职业队的做法就是**直接 ban 体系核心件**，而不是去 counter 射手。
3. 鲁班大师被 ban 87.4%，是全场第一 —— 他是「弹弓」「鲁班父子」「移动炮台」三套体系共同的核心件，**一个英雄锁三套体系**，所以必 ban。

### 5.2.2 组合在 KPL 的真实表现（严格口径：核心件命中 ≥2）

| 组合 | 我方定档 | 出现局数 | 满编局数 | 胜率 | 判读 |
|---|---|---|---|---|---|
| 小乔钟馗 | S | 29 | 29 | **48.3%** | 高出场、不强势：被职业研究透了，专项反制成熟 |
| 朵莉亚刷大·双边 | A | 18 | 0 | 55.6% | 体系骨架常用，但很少五人满编 |
| 刀枪炮 | S | 9 | 0 | **66.7%** | 出现就有效，符合「无明显弱势期」 |
| 大禹手长消耗队 | B | 8 | 0 | 62.5% | 新体系，样本尚可 |
| 双坦不死流 | B | 7 | 0 | **71.4%** | 本样本里胜率最高的成型体系 |
| 元狄 | A | 6 | 6 | **66.7%** | 满编即成型，胜率可观 |
| 其余 9 套 | — | ≤3 | — | — | **样本不足，不要下结论** |

### 5.2.3 这批数据提示了什么（仅参考，不改天元口径）

- **「小乔钟馗是 S 档必抢」在 KPL 不成立**：29 局满编只有 48.3%，职业层面属于「能打但不占优」。
  但这**不能**据此降档：组合档位是机制层结论（§2.3，控制链闭环 + 上手门槛低），KPL 只说明「职业队有成熟反制」。
  两者不矛盾——巅峰对决是盲选无 ban 能稳定拿到；常规 BP 里对手会用庄周/东皇专门拆。
- **刀枪炮、双坦不死流、元狄在 KPL 表现好**（样本 ≥6、胜率 ≥66%）：可作为机制的旁证，但**不能反向覆盖天元的 tier/counter**。
- **「ban 体系核心件」被印证**：盾山 69.8%、鲁班大师 87.4%、钟馗 34.6%（T2）—— 职业队 ban 的从来不是梯度，是组合。
- **不是「冲突」，是分工**：天元 ban 率反映「路人对手会 ban 谁」，KPL ban 率反映「职业体系件值多少」。同一个英雄两边差异大是**信息而不是矛盾**——鲁班大师 2.8% vs 87.4%，恰恰说明他是「职业必 ban、路人没人管」的体系核心。
- **tier 与 KPL 胜率分歧**（如天元 T0 但 KPL 胜率不到 50%）：tier 仍是强度基准，KPL 用来解释「为什么这个 T0 在职业不好赢」（被针对、体系不适配）。两者一起进整合分，不互相否决。
- **KPL ≠ 五排路人局**：职业有教练、针对性 ban、五人执行度高；路人局更吃个人操作与配合。所以 KPL 在整合里占 45%（略低于天元的 55%），且只进 ban 分与组合修正，不单独改写 tier。

### 5.2.4 数据本身的局限

- 只有 BP 集合，**没有 ban/pick 顺序**（接口 `position` 字段全为 0），所以无法分析「第几手抢什么」。
- 159 局里单个组合的样本仍偏小（≥5 局的只有 6 套），其余只能当趣闻。
- 该赛事为「2026 KPL 年度总决赛」前段（10-02～10-22，40 场已结束），不含 10-27 之后的对局。

### 5.2.5 怎么用（三方整合后）

1. **ban 排序直接用 `integration-v1.json` 的 `banValue`**：天元 ban 率 55% + KPL ban 率 45% + 单卡强度 20%。
   实测前列：盾山 0.745（双环境必 ban）> 鲁班大师 0.607（职业体系件）> 海月 0.587 > 墨子 0.462（路人恶心件）> 关羽 0.442 > 钟馗 0.429（双环境必 ban）。
2. **预选阵容看 `regime` 字段**：`kpl-only`（职业体系件，路人没人 ban）说明我方容易拿到，值得直接选；`ranked-only`（路人恶心件）说明对面大概率 ban 它，要做好替补。
3. **组合定档按 `combos.json` 的 priority**；组合的 KPL 实测胜率**只作提示**（在 UI 里写「职业 29 局 48.3%」），不参与档位修正——职业被针对不等于路人弱。
4. **现场查询**：`node tools/combos-probe.mjs 钟馗` 会显示组合完成度 + KPL 实测 + 拆解点。

### 5.3 三方整合模型（`data/integration-v1.json`）

由 `tools/integrate-data.mjs` 生成，参数集中在脚本顶部 `CONFIG`（便于按反馈调参）。每个英雄一条：

```jsonc
{
  "hero": "钟馗",
  "tier": "T2",
  "tianYuan": { "score": 34.92, "banRate": 36.93, "pickRate": 10.2, "winRate": 48.17 },
  "kpl": { "banRate": 34.6, "pickRate": 20.8, "winRate": 45.5, "sample": 159 },
  "score": { "solo": 0.349, "ban": 0.429 },   // solo 只算单卡；ban 才是两套 ban 率融合
  "comboPotential": {                          // 仅提示，不进排序
    "value": 1.0,
    "memberships": [{ "id": "xiaoqiao-zhongkui", "role": "core", "priority": "S" }]
  },
  "regime": "both"        // both=双环境必ban｜kpl-only=职业体系件｜ranked-only=路人恶心件｜mixed｜low
}
```

**关键：单卡与组合必须分开看。**

| 英雄 | 天元 T 度 | `solo`（单卡） | `ban` | `comboPotential` | 解读 |
|---|---|---|---|---|---|
| 盾山 | T0 | 1.000 | 0.745 | 1.00 | 单卡本就最强，且是两套体系核心 |
| 鲁班大师 | T0 | 0.993 | 0.607 | 1.00 | 单卡强 + 职业必 ban（三套体系枢纽） |
| 小乔 | T1 | 0.583 | 0.152 | 1.00 | 单拿就是 T1；只有和钟馗一起才结算组合 |
| 墨子 | T2 | 0.371 | 0.462 | 1.00 | 单拿 T2；ban 价值高是因为恶心/能凑刀枪炮 |
| 钟馗 | **T2** | **0.349** | 0.429 | 1.00 | **单拿就是 T2，不会因组合被抬到 T0 之上** |

> ⚠️ 这里刻意纠正过一版错误实现：早期我把「组合价值」摊到单卡 pick 分上（于是 T2 的钟馗/墨子压过 T0），
> 这是错的——**「拿齐小乔钟馗 ≈ 两个 T0」说的是组合成型给团队的总增量，不是分给两个人的个人分**。
> 正确做法：单卡 solo 不变，组合加成由引擎在「成型那一刻」结算（`web/engine.js` 的 `presetFitOf`：核心件 `(20 + 2.2×tierW) × 阶段系数`，两件核心合计 ≈ 2 个 T0 量级）。

**消费方式**：`node tools/integrate-data.mjs` 生成数据；服务端提供只读接口 `GET /api/integration`（返回本文件，version 2.0）。
UI 若要用，只应展示 `score.ban` 与 `comboPotential`（提示），**不要用它替代引擎的 pick 打分**。

## 6. 接进 BP 引擎的方案（v2.4 已按「预选模板」路线实现）

> **现状**：本节原为「通用组合加分」的建议（新增 `weights.combo`、`compMatchOf`）。v2.4 实际采用的是
> **「预选阵容」路线**——用户在 BP 前显式选一套体系，引擎通过 `web/engine.js` 的 `presetFitOf` 给分：
> 核心件 `(20 + 2.2×tierW) × 阶段系数`（grab 1 / mid 0.95 / counter 0.9）、搭配位 `8 + 4×synergy`、契合位 `3×fit`；
> ban 侧强制 must 优先。这与「拿齐才结算、不摊到单卡」的口径一致，且比隐式组合识别更可控。
> 下文保留作设计对照与后续扩展参考。

### 6.3 引擎侧改动（`web/engine.js`）

1. **新增权重键** `combo`（建议 1.34，可在 UI 调），并加进 `weightKeys` 白名单（`build-meta.mjs` 与 `validate-data.mjs` 的 `WEIGHT_KEYS` 需同步）。
2. **新增 `compMatchOf(ctx, hero, ally)`**：返回 0–1 的组合完成度增益。

   ```
   对每个 combo：
     have = |core ∩ ally|                    // 已命中核心件
     若 hero 属于 core 或 flex 可替代位:
       if have >= 1:                        // 至少已有一件，才值得凑
         gain = PRIORITY_W[priority] × (have + 1) / size
         若 core 全部命中（have+1 == size）: gain × 1.35   // 组合成型的额外奖励
     取所有 combo 的 max（避免多组合重复叠加）
   ```
3. **打分公式追加一项**：
   ```
   compNeed  = 1.4 × phase.compNeed × compNeedOf(...)      // 原有：补阵容缺口
   combo     = 1.34 × phase.combo × compMatchOf(...)       // 新增：凑组合
   score     = ... + compNeed + combo
   ```
4. **阶段系数（关键，体现「组合大于克制」）**：

   | ourPickNo | phase | tier | counter | synergy | compNeed | **combo** |
   |---|---|---|---|---|---|---|
   | 1–2 | grab | 3.0 | 0.25 | 0.7 | 0.4 | **1.2** |
   | 3 | mid | 2.0 | 1.1 | 1.1 | 1.0 | **1.6** |
   | 4–5 | counter | 0.5 | 3.0 | 0.9 | 0.9 | **1.0** |

   理由：第 3 手是「定体系」的窗口（组合权重最高）；第 1–2 手拿到组合核心也值钱；第 4–5 手让位给克制（但仍保留 1.0，避免为了假克制拆自己组合）。
5. **ban 侧**：不建议改 v2.1 的「强度主导」。只在 UI 加一条提示：**「对面已出 X，可 ban Y 拆组合」**（用 `counteredBy` 反查）。例如对面出钟馗 → 提示 ban 庄周；对面出盾山 → 提示出真伤/绕后。
6. **UI**：候选卡上加组合标记（`可组成：小乔钟馗 2/2`），已选区显示「当前体系：刀枪炮 3/5」。
